# 2026-07-27

### 新增

- **Anthropic 渠道新增「Claude Code 兼容」开关（`claudeCodeCompat`）**：上游是 Claude Code OAuth 代理
  （CLIProxyAPI 等）时，代理会对「不像 Claude Code 的客户端」做 cloak —— **把客户端发的 `system`
  整段丢掉**，换成它自己那份 ~1900 token 的 Claude Code 系统提示词。结果是客户端注入的人设、记忆、
  工具约束全部失效。排查过程：llmgateway 自己的 `console_requests` 表里 `original_payload` 与
  `forwarded_payload` 的 system 都完好，进 cliproxyapi 容器直连 `127.0.0.1:8317` 复现丢失，
  确认是那一跳；它的 `config.example.yaml` 里也写着这个行为（`cloak.strict-mode`），
  但那段配置只对 `claude-api-key` 条目开放，OAuth 授权文件走的路径没有开关可调。

  **做法：把 `system` 原文搬进第一条 user 消息，请求体不再带 `system`。** cloak 只动 system、
  不碰 messages，所以内容能原样抵达模型。搬运细节：
  - 内容包在 `<system_instructions>` 里，前面加一句说明（这些是应用方的指令，当成 system 遵循），
    和用户真正说的话有清晰边界
  - Anthropic 要求 user/assistant 严格交替，所以不能新插一条 user 消息，只能作为第一条 user
    消息的**首个 text block** 塞进去；用户原有内容（含图片等多模态块）原样跟在后面
  - system 是 block 数组时合并文本，**末块的 `cache_control` 跟着搬过去**，缓存边界不变
  - 搬的是第一条 **user** 消息（不是第一条消息）；渠道自身的 `systemPrompt` 注入完再搬，
    所以渠道级 system 也一起走
  - 没有 user 消息可搬、或 system 为空时原样返回，不制造空块

  这个方案不替客户端改提示词内容，也不伪装客户端身份；代价是 cloak 依然生效，
  那份 ~1900 token 的 Claude Code 提示词还在（走缓存读，成本可忽略）。
  开关只对 anthropic 渠道有效（存/取时都会按类型强制关掉），官方 Anthropic API 不要开。
  DB 新增列 `console_providers.claude_code_compat`（pg migration `0011`、sqlite migration `0001`），
  默认关闭，老渠道行为不变。控制台供应商表单在 Anthropic 类型下多一个勾选项（zh/en 文案齐全）。

  实测（sonnet-5，直连 cliproxyapi 复现 cloak 环境）：开启前 system 里的信息模型答「不知道」、
  自我介绍答「我是 Claude Code」；搬运后「你是谁」按客户端人设答「我是 ChatFlex」、
  system 里写的用户信息也答得出来。另有 7 个单测覆盖字符串/数组 system、多模态 user 内容、
  首条是 assistant、无 user 消息、空 system、开关关闭六种情形。
