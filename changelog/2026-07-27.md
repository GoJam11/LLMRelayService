# 2026-07-27

### 新增

- **Anthropic 渠道新增「Claude Code 兼容」开关（`claudeCodeCompat`）**：上游是 Claude Code OAuth 代理
  （CLIProxyAPI 等）时，代理会对「不像 Claude Code 的客户端」做 cloak —— **把客户端发的 `system`
  整段丢掉**，换成它自己那份 ~1900 token 的 Claude Code 系统提示词。结果是客户端注入的人设、记忆、
  工具约束全部失效，模型还自称「我是 Claude Code」。开启本开关后网关会补两样东西，代理就不再 cloak、
  原样透传：
  - `buildForwardHeaders` 补 `user-agent: claude-cli/2.1.44 (external, cli)`
    —— 这是代理判断客户端身份的依据；客户端自己就带 `claude-cli/` 前缀时保留它的版本号
  - `prepareRequest` 把 Claude Code 身份行插成 `system` 的第一块
    —— Anthropic 的 OAuth 端点要求它在，只改 user-agent 不加身份块会直接 `auth_unavailable`

  两件缺一不可（实测：只加身份块不改 UA 仍被 cloak；只改 UA 不加身份块上游报错）。身份行**单独成块**，
  不和客户端提示词拼成一个字符串 —— 拼在一起会共用一个缓存块，身份行变一个字节客户端整段 prompt cache
  就失效。注入顺序在渠道 `systemPrompt` 之后，保证身份行始终是第一块。
  开关只对 anthropic 渠道有效（存/取时都会按类型强制关掉），官方 Anthropic API 不要开。
  DB 新增列 `console_providers.claude_code_compat`（pg migration `0011`、sqlite migration `0001`），
  默认关闭，老渠道行为不变。控制台供应商表单在 Anthropic 类型下多一个勾选项（zh/en 文案齐全）。

  实测（sonnet-5 / haiku-4.5 / opus-5，流式与非流式）：开启前 system 里的金丝雀信息模型答「不知道」、
  自我介绍答「我是 Claude Code」；开启后金丝雀正确、按客户端人设自我介绍，工具调用正常，
  7505 token 的长 system 首次 `cache_creation=7505`、第二次 `cache_read=7505`，
  且每次请求少 ~1900 token 的注入。
