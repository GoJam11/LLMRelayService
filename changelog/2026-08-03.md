# 2026-08-03

### 修复

- **计费取价改为「响应模型 → 请求模型」回退，修复中转渠道整条请求按 0 计费（看起来像"没计缓存"）**：
  线上 `CPA-Claude` 渠道的 claude-sonnet-5 请求，128 条里成本全是 $0，缓存价格明明已经配好。

  根因有两处，叠加起来正好把缓存成本抹成 0：

  - **取价只认响应模型**：`resolveRequestPricing()` / `resolveRowPricing()` 都只用
    `response_usage.model` 去查价目表和手动覆盖价。但中转上游（cliproxyapi）在响应里返回的是
    自己的代号 —— 线上实测 `openclaw`、`code` —— 而不是真实模型名，价目表和「模型」页配的
    自定义价（按渠道模型 ID `claude-sonnet-5` 存）一个都对不上，`pricing` 为 null，
    **整条请求按 0 计费**。这类请求 input 只有 2 个 token、成本几乎全在缓存读写上，
    表现出来就是"缓存没计费"。现在取价按候选模型依次尝试：响应模型 → 请求模型，
    且**手动覆盖价整体优先于价目表**，避免响应模型恰好在价目表里、请求模型上配的自定义价被忽略。
  - **读路径从不加载价目表**：价目表是 pricing 模块的进程内缓存，只有 `ensurePricingLoaded()`
    才会填充，而日志列表 / 日志详情 / 用量统计这些读路径（行上没有 `cost_pricing_json` 快照时
    要按当前价现算）从来没调用过它。冷启动后一直到有人打开「模型」页之前，`getModelPricing()`
    对所有模型都返回 null，成本一律显示 0。三个读路径补上加载（失败只告警，不影响出日志）。

  修复后线上那条真实样本（input 2 / output 49 / cache_creation 24802 / cache_read 56069）
  从 $0 变为 $0.073713（input $0.000004 + output $0.000490 + 缓存读 $0.011214 + 缓存写 $0.062005）。
  历史行里 `cost_pricing_json` 为空的（就是这批算成 0 的），日志与用量页会按当前价重新计算，
  不需要回填；已扣的 API Key 额度（`quota_charged_microusd`）保持原样，不追溯改写。

### 新增

- **日志右侧面板恢复「成本明细」卡片**：master-detail 改版时这块被删掉了，导致日志里只能看到一个
  总成本数字、无法判断缓存有没有计进去。现在默认 tab 顶部展示总成本、模型单价（缓存读/写单价，
  兜底价标「（推导）」）以及逐项计算公式（输入 / 输出 / 缓存读 / 缓存写，1h 缓存写会拆成 5m、1h 两行）。
  - 响应模型和实际计价模型不一致时（如响应 `openclaw`、按 `claude-sonnet-5` 计价）多显示一行
    「计价模型」，接口新增 `response_usage.cost_pricing_model` 字段。
  - 缺价时的提示点名具体模型，并指向「模型」页配置。
  - 明细里的金额改为保留 6 位小数（原来两位会把 $0.011214 显示成 $0.01，逐项加起来对不上总成本）。
